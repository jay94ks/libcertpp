# Constant-time 및 성능 작업

[English](performance.md)

이 문서에는 아직 남은 작업만 둡니다. 현재 벤치마크 결과와 방법론은
[성능](../concepts/performance.ko.md)에, 완료된 최적화·조사·부정적 결과는
[변경 이력](../HISTORY.ko.md)과 [계획에 없음](not-planned.ko.md)에 기록합니다.

## 보안 작업

- **소수 곡선 ECDH와 ECDSA 서명의 constant-time 전환을 마칩니다.** ladder는
  이제 군 위수의 전체 폭을 처리하고 레지스터를 mask로 교환하며 비밀 의존 고정
  기저 테이블을 사용하지 않습니다. 남은 장애물은 `CBigNum` 자체입니다. 가변 폭
  limb를 할당하고 잘라내며 산술 비용이 피연산자에 따라 달라집니다. 지원하는 소수
  곡선 전반에 공유할 고정 폭 필드 전략이 여전히 필요합니다.
- **ML-DSA 서명의 타이밍 누출을 감사합니다.** Fiat-Shamir-with-aborts의 재시도
  횟수는 설계상 데이터 의존적입니다. 현재 구현은 비밀 중간값을 지우고 한 반복
  안에서는 비밀에 따른 테이블을 피하지만, 공개된 Dilithium 공격을 기준으로 한
  전용 타이밍 부채널 검토는 아직 받지 않았습니다. [PQC 엔지니어링과
  위험](../pqc/engineering.ko.md)을 참고하십시오.

## 성능 조사

- **GCC의 DSA를 프로파일링합니다.** 기록된 WSL2 머신에서는 두 빌드가 같은
  `CBigNum` 백엔드를 쓰는데도 GCC의 DSA-2048 서명과 검증이 MSVC보다 크게
  느렸습니다. 코드를 바꾸기 전에 bare-metal Linux에서 격차를 재현하고,
  재현된 경우를 프로파일링합니다.
- **GCC의 이진 곡선을 프로파일링합니다.** WSL2 비교에서 GF(2^m) 곡선 열 개가
  모두 같은 방향으로 움직여 공유 `CGf2m` 코드를 가리켰습니다. bare-metal
  Linux에서 재현하고 공유 비용을 분리한 뒤 최적화를 제안합니다.
- **검증용 공개 키 테이블을 평가합니다.** 서명 검증은 가변 기저를 쓰지만 인증서
  발급자 키는 흔히 재사용됩니다. 공개 키마다 테이블을 캐시하는 것이 메모리와
  준비 비용을 감수할 만큼 해당 작업 부하를 개선하는지 측정합니다.

모든 최적화는 재현 가능한 기준값과 프로파일에서 시작합니다. 벤치마크 머신의
실행 간 편차보다 작은 변화는 개선으로 간주하지 않습니다. 받아들인 변경은 관련
기지 응답 및 네거티브 테스트를 계속 통과해야 합니다.
